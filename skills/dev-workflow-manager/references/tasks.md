# 任务、状态与存储

## 默认存储：同一目录，每周一个 Markdown

需求、Bug、优化、维护统一写入项目根目录的 `docs/dev-workflow/weekly/`，文件名为 `YYYY-Www.md`，如 `2026-W46.md`。项目明确指定其他目录时沿用；不要把记录写进 Skill 安装目录。默认无需腾讯文档、数据库或外部平台。

以用户时区计算 ISO 周：周一至周日，文件年份使用 ISO 周年（跨年时可能不同于日历年）。标题同时注明起止日期。按需创建当周文件，不预建全年文件。一个周文件包含任务概览表和每个任务的详情，需求与 Issue 用类型区分，不再每个任务建一个文件。

用户明确要求登记或跟进时写入记录；仅要求修复或提交时先关联已有记录，无记录则不强制新建。登记前搜索整个记录目录，而非只搜当周，先按编号查找，再按目标端、页面、现象和复现条件查重。相似但不确定时保留候选，不能自动合并或关闭。

沿用已有编号规则；默认 `TASK-YYYYMMDD-001`，需求和 Issue 共用每日序号，以用户时区登记日期生成。保存前搜索整个目录确认唯一，并重新读取目标文件避免覆盖他人更新；并发冲突时重新分配编号，无法可靠分配则使用唯一后缀并说明。外部需求编号另存，不能用内部编号冒充 XQBH。

## 每周文档模板

```markdown
# YYYY-Www 需求与 Issue

周期：YYYY-MM-DD（周一）至 YYYY-MM-DD（周日）
时区：用户时区

## 本周登记

| 编号 | 类型 | 标题 | 目标端 | 状态 | 外部需求编号 |
| --- | --- | --- | --- | --- | --- |

## 跨周跟进

暂无。需要时添加原始任务的相对链接、当前状态摘要与本周跟进事项。

## 任务详情

<!-- 新任务按以下结构追加；尚无任务时不放虚构任务。 -->

### TASK-YYYYMMDD-001 标题

- 类型：bug / feature / improvement / maintenance
- 登记时间：包含用户时区
- 更新时间：包含用户时区
- 来源：用户反馈、需求链接等
- 状态：待处理
- 外部需求编号：无，或真实编号
- 影响端：
- 本次实施端：
- 优先级：未分级，或项目已有分级
- 负责人：未指定，或真实负责人
- 页面路径：已确认路径；无法确认则写待确认
- 路由或模块：

#### 目标与范围
具体问题、预期行为、本次边界。

#### 复现（Bug）
发生环境、前置条件、操作步骤、实际结果和预期结果。

#### 验收标准
可观察、可判断的结果。

#### 开发与验证记录
日期、分支、实际修改、自检结果、未验证事项及证据位置。

#### 交付记录
Commit（可多个）、推送与发布情况、验收依据和下一步。
```

维护概览表与详情状态一致；表格值中的竖线转义。详情标题以稳定任务编号开头，链接使用实际 Markdown 标题锚点；引用时优先带相对文件路径和任务编号，避免仅凭锚点定位。

## 跨周与旧记录

原始登记周的详情是唯一权威记录：跨周不迁移、不重编号、不复制整份任务。后续进展追加到原始详情，更新其状态、更新时间和概览表；当前周的“跨周跟进”只放相对链接、状态摘要和本周事项。只有实际跟进才加引用，不自动把所有未完成任务复制到每周。

关闭、重开或补充验证都更新原始任务。日报和周报既查本周新增，也查历史任务的本周活动，不能把“本周登记”当成“本周完成”。

若已有一任务一文件等旧记录，继续可查可引用，新登记采用周文件；只有用户明确要求整理旧记录时才迁移，并保留编号与引用。用户明确指定外部权威任务源时，周文档作为本地索引，注明权威链接，避免双向静默覆盖。

未知信息写未确认，不虚构优先级、负责人、页面或验收结果。一个任务可以关联多个 Commit；一个 Commit 只能包含连贯修改。先提交代码再回填最终哈希，文档需要入库时按已有授权另行提交，不为把提交自己的哈希写入同一 Commit 而反复 amend。

## 状态转换

- 待处理：已登记，尚未实施。
- 处理中：已开始定位或修改；验证失败也回到此状态。
- 待验证：修改完成，开发自检及未验证事项已记录，等待约定的验收。可以尚未提交，需标注。
- 已完成：验收标准已通过，有真实证据。若交付标准包含发布，发布完成前不能关闭。
- 受阻：明确阻碍，记录恢复条件；不能把单纯尚未完成视为受阻。
- 已取消：用户或权威任务源明确取消，记录原因。

各端独立记录实施与验收结果。某端验证通过不代表其他端完成。报告可以写“代码已提交，待设备验收”。

## 同步失败

外部创建或更新返回不确定结果时，先查询是否已经成功，禁止盲目重复创建。以任务 ID 和 Commit 哈希去重追加。无法确认时保留本地待同步记录，注明目标、操作、失败原因和已知结果，避免记录凭证。只重试失败环节；权限不足或目标不明确时停止外部写入。
