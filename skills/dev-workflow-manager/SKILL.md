# 开发流程管理

让每个开发任务能够追溯目标、代码、验证证据和当前状态。按用户要求从相应环节进入，不强迫每次走完整流程。

## 确认上下文

读取适用的 AGENTS.md、项目现有提交约定和任务记录。默认使用当前分支，不主动切换、同步或查询其他分支；跨端参考遵守项目授权。区分任务影响端、本次实施端和已验证端。

项目明确规定的提交格式优先；未规定时采用本 Skill 的完整格式。只有 AUTHOR/XQBH/NOTES 元数据约定的项目，采用完整格式并保留这行元数据。不得未经要求修改项目配置或安装 Git hook。

## 按需执行

- **登记、关联、恢复任务**：读 [任务与状态规则](references/tasks.md)。默认在项目 `docs/dev-workflow/weekly/` 的每周 Markdown 中统一记录需求和 Issue，每周一个文件；具体周界、编号、跨周跟进和模板见该参考。项目明确指定其他记录目录时沿用该目录。普通修复请求不强制新增任务，已有任务则回填。外部平台仅在用户明确要求时关联，不默认同步。
- **实施与验证**：先明确范围和可观察的验收标准；缺少非关键字段可继续工作。使用与变更有关的构建、测试或人工检查，分别记录通过、失败、未执行及其原因。已有规则要求查文档时照做。
- **生成或执行提交**：必须读 [Commit Message 协议](references/commits.md)，对照实际变更生成消息。默认只实施和汇报；“生成说明”不提交，“提交一下”授权本地提交。已有授权足够时不重复确认；提交授权不自动包含推送、合并和发布。
- **回填与交接**：保存任务编号、实施端、代码位置、验收标准、实际验证、提交哈希和下一步。区分提交、推送、发布、验收；不将提交成功直接标成任务完成。

## 提交执行约束

检查工作区、暂存区和未跟踪文件，分清任务相关变更与用户已有修改。只暂存本任务范围，不使用全量暂存吞入无关修改；同一文件混有无关修改时使用精确暂存，不能安全分离才询问。提交前再次检查暂存 diff；不重置用户已有暂存，不绕过 hook，不擅自 amend。

完整格式消息写入临时文件，执行：

```text
python3 <skill-dir>/scripts/validate_commit.py <message-file>
```

脚本只检查格式。代理仍需核实描述与实际暂存 diff、作者、任务关联、页面路径和验证证据是否一致。校验通过后用消息文件执行提交；若项目使用不同的明确格式，按该项目规则校验，不用本脚本强行否决。

提交或同步报错时先核实实际结果。提交成功而任务回填失败，只重试回填；一次纠正性重试后仍失败则保留待同步事项并报告，避免重复副作用。

## 输出

按用户请求简要交付：任务编号或未登记说明、修改结果、实际验证及缺口、提交哈希（仅实际成功时）、当前状态和下一步。日报基于实际任务和 Git 证据，不把分析计划算作完成。
